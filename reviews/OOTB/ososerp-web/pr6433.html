This PR adds Portfolio and Program master screens to the PMO feature (lazy-loaded routes, services, resolvers, list/detail pages, table metadata and i18n). It also adds portfolio/program structure selection to the project form, a new save-error handler, and a payload change in ProjectService. It covers OOTB-15763 and OOTB-15766 in about 2.6k changed lines.

Merge is blocked by corrupted-encoding (mojibake) text in the en-US confirm message, which users will see in the confirmation dialog. The same encoding problem affects the separator constant, and the ar-OM additions should be checked. The PR description is the unfilled template, and there are no tests for the new cascade, revert and validator logic.

The team should confirm that the new TableType values (417/418) and the portfolio/title filter path match the backend. They should also decide whether loading 10000-row dropdowns is acceptable, and whether to split the PR.

F3 (PR-level)

Empty description, no tests, two tickets bundled. The PR description is the unfilled template (no What/Why), so reviewers have no stated intent to check the code against.

F4 libs/features/pmo/src/lib/program/services/program.resolver.ts:28

Unbounded 10000-row dropdown loads, errors swallowed. Portfolios and programs are loaded with a page size of 10000 in the program resolver and in the project detail page, which fetches both on every project open. This will not scale, and it is not filtered to active records. A typeahead or a lightweight endpoint would be better. Also at: libs/features/pmo/src/lib/project/containers/project-detail-page/project-detail-page.component.ts:346.

F5 libs/features/pmo/src/lib/portfolio/services/portfolio.resolver.ts:17

Resolvers lack error handling. getById has no catchError. A missing, soft-deleted or other-tenant id leaves the navigation failing with no feedback to the user. The same applies to selectedProgramResolver. portfoliosResolver also fails the whole program page if the dropdown call errors, whereas the project page handles this with catchError.

F6 src/assets/data/pmo/program.json:41

Verify program column path portfolio/title. The Portfolio column is isInsideObject with path portfolio/title and allowedFilters 6, so it is filterable, even though allowSearch and allowSort are false. The path must match Program.Portfolio.Title on the backend entity. Please verify that. If the filter isn't supported, set allowedFilters to empty.

F7 libs/core/enums/src/lib/enums/table-type.ts:414

Confirm TableType values match backend. New members ProjectPortfolio = 417 and ProjectProgram = 418 follow LoanType = 411, leaving a gap. If these numbers are not intentionally matched to the backend enum, the user-columns API may map to the wrong table. Please confirm the values match the backend.

F8 libs/features/pmo/src/lib/portfolio/services/portfolio.service.ts:52

Empty value fires uniqueness request. The validators encode the value with encodeURIComponent, and the service then interpolates it into the path. Angular does not re-encode it, so this is probably fine. However, an empty code or title still fires a request to /code/, which hits a different route. An empty value should short-circuit with null. The same applies to program.

F9 libs/features/pmo/src/lib/portfolio/models/table-metadata.ts:88

Column name updatedBy inconsistent with createdByName. The column def and JSON name are 'updatedBy' while the path is updatedByName. The i18n keys include both createdByName and updatedBy. The inconsistency with createdByName is confusing. Check that user column selection matches on name. The same applies to program.
