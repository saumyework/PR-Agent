This PR adds KPI count cards to the SDM requests list page. The cards load counts from a new GET sdmRequests/counts call, and users can show or hide them, with the choice saved per user and company. It also rewrites the emails-to-notify chip behaviour and styling, which is unrelated to the KPI work.

Nothing is a hard blocker. Fix these before merge: stale KPI counts on error, counts that don't refresh after a delete or edit, and the autocomplete-close commit that can add the wrong recipient. The PR description is empty, there are no tests, and the backend /counts endpoint is not in this PR.

The team should decide whether the emails-to-notify changes move to their own PR, and should confirm the backend counts endpoint is deployed. They should also confirm it uses the same company, requester and soft-delete scoping as the list endpoint.

F2 libs/features/sdm/src/lib/requests/containers/requests-list-page/requests-list-page.component.ts:183

KPI load failure leaves stale counts on screen. When getKpiCounts fails, catchError shows a toast and returns EMPTY. kpiCounts keeps the previous filter's numbers, so the cards no longer match the list. Set kpiCounts to null on error, for example by returning of(null), so the cards show the dash placeholder.

F3 libs/features/sdm/src/lib/requests/containers/requests-list-page/requests-list-page.component.ts:178

distinctUntilChanged stops counts refreshing after data changes. Counts are re-fetched only when the filter params change. getAll also fires after a delete or after returning from create/edit, and in those cases the filter string is identical. The list reloads but the KPI cards keep the old total, active and other counts. Consider refreshing on every getAll and de-duplicating only page-change reloads, or add an explicit refresh trigger.

F4 libs/features/sdm/src/lib/requests/components/request-emails-to-notify/request-emails-to-notify.component.ts:134

Autocomplete close auto-commits partially typed text. commitPendingNotifyText runs on every autocomplete (closed) event, including Escape and blur. #recipientFromToken accepts a partial string that matches exactly one user, so typing "joh" and clicking away adds that user without an explicit choice. With matChipInputAddOnBlur now false, typed text is committed only if the panel was open and then closed. The #selectedFromList flag, reset in a microtask, depends on the order of the optionSelected and closed events and could add a duplicate. Commit on close only for exact matches or valid emails, and add tests.
