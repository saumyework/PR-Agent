This PR adds a Resource Levelling Gantt view (v2) to the PMO resource plan: drag-drop reassignment, an edit dialog, publish/revert, a date navigator, a shared workload helper, a deactivate guard, new i18n keys, and a rename of the old Gantt to V1. The PR is open, large (about 4,250 lines across 53 files), mixes in unrelated churn, and has an empty description.

Blocking issues are data-integrity risks in the v2 Gantt. The row drop has no error handling and mutates the shared resource id. The edit dialog round-trip overwrites task fields with hard-coded defaults that are then published. Removed export-warning i18n keys may still be used by v1.

The team should decide whether to split the PR and add tests for the new leveling logic.

Method: 6 independent review calls over 2 shard(s), evidence machine-checked (0 unverifiable candidates discarded), then one merge call.

Must-Fix

F1 libs/features/pmo/src/lib/project/components/resource-gantt-chart-v2/resource-gantt-chart-v2.component.ts:724

Row drop: no error handling, id mutated. The taskResourceService.update subscription in the row drop has no error handler, so a failed call leaves the UI and server inconsistent without any message. The drop also replaces the resource id with the target projectResourceId. #mapTaskRequestData later uses resource.id for both id and projectResourceId, which can corrupt the TaskResource mapping on publish. The drop is persisted immediately, yet Revert only reloads tasks and cannot undo it, so Revert/Publish semantics are inconsistent.

F2 libs/features/pmo/src/lib/project/components/resource-gantt-chart-v2/resource-gantt-chart-v2.component.ts:1099

Edit round-trip overwrites fields with defaults. #mapTaskRequestData fabricates a TaskRequest with hard-coded values (mode: TaskMode.Auto, taskType: TaskType.Parent for every task, isAvailable: true, isDeleted: false). The dialog result goes through #mapGanttData, which hard-codes mode: 'Auto', wbs: undefined, and level derived only from parentTaskId. #applyTaskUpdate then spreads this over the existing task ({ ...task, ...updatedTask }). Editing any task in the leveling Gantt can therefore silently reset Manual-mode tasks to Auto, clear wbs, and replace level. Publish then sends bulkInsertUpdate with this.tasks(), so the corrupted values are persisted. Only the fields the dialog actually edits should be merged back.
