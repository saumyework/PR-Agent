The PR adds a Resource Leveling Graph component. It rewrites the allocation helper to use working-hours-weighted per-day shares, and it adds a resizable Gantt container and over-allocation indicators. It also adds an unsaved-changes dialog when switching views, plus en-US and ar-OM translations.

Nothing here is a definite bug, but the PR description is the unfilled template. The allocation maths change for every resource and ship with no unit tests, so merge should wait for a description and specs covering the edge cases. The team should decide whether the unrelated unsaved-dialog change stays in this PR.

Smaller points: resize should clamp rather than drop updates, the chart is rebuilt on every change through a JSON key, the indicator sync pairs rows by index, and the 'h' unit is not localized.

F1 (PR-level)

Empty PR description and no tests. The PR template was left unfilled, so there is no stated intent or ticket context. The rewritten allocation logic in resource-leveling-helper.ts (buildTaskDayShares, hasDayLevelOverlap, allocatedHoursWithinColumn), the graphPeriodsByResourceId window filtering and the parentTaskbarSegments end-date handling ship with no spec files. Add a description and unit tests for weekends, holidays, zero-working-hour tasks, end before start, midnight end dates and the week/month/project windows.

F2 libs/features/pmo/src/lib/project/components/resource-plan-list/resource-plan-list.component.ts:89

Unrelated unsaved-changes dialog on view switch. setViewMode now opens UnsavedDialogComponent and manipulates the toggle group value. This is unrelated to the resource graph feature, and it is not mentioned in the PR title or description. It should be called out or split into its own PR. While the dialog is open, further toggle clicks can open stacked dialogs, because there is no guard.

F3 libs/features/pmo/src/lib/project/components/resource-gantt-chart-v2/resource-gantt-chart-v2.component.ts:653

Indicator sync assumes row/index alignment. Row DOM elements are paired with currentViewData by index. The pairing breaks if the grid is virtualized, sorted, filtered or paged differently from currentViewData, or if collapsed child rows are not rendered. Indicators could then be attached to the wrong resource. Matching on the row's data-uid or the row's own data would be safer.

F4 libs/features/pmo/src/lib/project/components/resource-leveling-graph/resource-leveling-graph.component.ts:123

Chart recreated via JSON.stringify key. chartKey stringifies the full dataset, colors, names and theme, and the @for track key destroys and rebuilds the whole chart on every change. This is wasteful and resets animation and state. Update the series in place, or key on a cheaper signature such as theme, RTL and language. The @defer (when data().length > 0) inside the @if is also redundant.

F5 libs/features/pmo/src/lib/project/components/resource-gantt-chart-v2/resource-gantt-chart-v2.component.ts:1450

Resize drops out-of-range heights; runs in zone. #setContainerHeight ignores heights outside [MIN_GANTT_HEIGHT, maxHeight], so a fast drag leaves the container short of the limit. Clamp instead. The document mousemove listener runs inside the Angular zone and triggers change detection on every move, so register it with runOutsideAngular. Resize is mouse-only, and the separator lacks aria-label, aria-valuenow, aria-valuemin and aria-valuemax. Also at: libs/features/pmo/src/lib/project/components/resource-gantt-chart-v2/resource-gantt-chart-v2.component.ts:1453.
