The PR fixes the root cause of the reported bug: requesters and technicians signals in SlaPolicyDetailPageComponent previously both resolved through the same generic getAll()-backed module-user-profiles call, so the technician dropdown effectively showed the same unfiltered list as requesters. This is replaced with a new availableUserListAsync(userType) endpoint call keyed off two new SDM_TECHNICIAN_USER_TYPE/SDM_REQUESTER_USER_TYPE constants, correctly filtering each list server-side. The diff also bundles in unrelated-but-reasonable SLA condition criteria fixes: a missing Validators.required on the criterion "value" control and three new mat-error bindings so validation errors actually render.

No must-fix issues. The main things worth tightening are a confusingly-named private field that shadows an inherited property in name only, two near-identical loader methods that could be collapsed into one, a signal that's declared and populated but never wired to the template, and a static required-validator that duplicates logic a dynamic sync method already owns elsewhere in the file.

libs/features/sdm/src/lib/admin/user-management/services/sdm-user-management.service.ts:22

Private field name shadows inherited property. readonly #apiObpUrl = `${this.apiObpUrl}/user-roles`; declares a private field whose name is nearly identical to the inherited this.apiObpUrl it reads from (from SdmBaseService). libs/features/sdm/src/lib/admin/sla-policies/components/sla-policy-condition/sla-policy-condition-details.component.ts:304

Static required validator duplicates dynamic logic. value: fb.nonNullable.control(formValue.value, Validators.required) sets a static validator, but #syncCriterionValueControlState (same file) already owns this control's required/disabled state dynamically based on triggerField/operatorType. For a row added via addCriterion(), #syncCriterionValueControlState isn't invoked until the user changes triggerField or operatorType — so between addCriterion() and that first change, the "value" control sits enabled and required even though no trigger field is selected yet (in practice masked by triggerField/operatorType also being required, but worth removing the static validator so the dynamic sync method stays the single source of truth).
