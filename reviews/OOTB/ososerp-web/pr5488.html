This is a grab-bag of SDM/RMS bug fixes: a real logic bug in hexColorValidator, required-field asterisks on several forms, an empty-state ("Unassigned") for the datatable's image/text column, a request-list search fix (searching by human-readable code instead of the GUID id), and two new "updated by/date" table columns. Changes are backward-compatible and mostly additive, but two of them touch shared, widely-used surfaces — datatable-v2 (used across many feature list pages) and the reusable osos-validators.ts/ErrorComponent pair — so a regression there has broad blast radius even though nothing found here looks broken. No spec files were touched despite the PR checklist claiming unit tests were added/updated, which is the main reason this isn't Low risk.

Error message moved outside its form field. <mat-error [ososError]="formControls.colorCode" /> was moved from inside <mat-form-field> to a sibling right after it, compensated by new padding-left/right: 30px and an overflow: visible override on .mat-mdc-form-field-error-wrapper. libs/shared/components/.../datatable-v2.component.html:539

Extra per-row function call in a shared, hot component. The new @if (column.emptyText && !column.cell(element)[1]) adds another direct invocation of column.cell(element) on top of the 3-4 calls already made for the same row/column in the branches below ([0], [1], [2], twice for [1]). cell() isn't memoized, so it re-runs on every change-detection pass for every visible row in every table using ImageText columns across the app. This compounds a pre-existing pattern rather than introducing a new one, but since this component is shared broadly, consider hoisting the result to a local via Angular's @let (or a memoized getter) to cut it back to one call per cell.

libs/core/src/lib/core/forms/osos-validators.ts:530

No regression test for the fixed validator bug. The old hexColorValidator (patternValidator(control, HEX_COLOR_CODE) ?? nullValidator) returned the nullValidator function reference itself — not its result — whenever the pattern matched, which is a truthy, non-null value Angular would have treated as a validation error, likely making the field permanently "invalid" even with a correct hex code. The new implementation fixes this correctly. Given the PR checklist claims tests were added/updated but no *.spec.ts changed in this diff (and osos-validators.ts has no spec file at all), a small unit test locking in this behavior would prevent the regression from silently coming back.
