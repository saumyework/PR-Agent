This PR adds SDM notification recipients and events. A new SdmNotificationService is called from the request and task create/update flows. The SLA job gets an {{Action}} token, and new NotificationTriggerAction constants are added. Failures are caught and logged so they can't break the main writes.

The new NotifySdmPublicCommentCommand handler loads a request by id with no company or access scoping. It also trusts the caller-supplied actor, author and body, and it has no validator. This blocks merge. Other issues need fixing too: the technician-change comparison bug, the Resolved to Cancelled 'reopened' misclassification, recipients not excluding the actor, and the client-controlled redirect URL.

The team should decide three things: whether hardcoded English text and reused notification categories and document types are acceptable for now, whether the unwired events (Approve, Reject, Public Comment, SLA breach, task due) belong in this PR, and whether the committed daily-notes file should be removed. The PR also has no tests and an empty description.

F2 src/Modules/Sdm/Sdm.Application/Services/RequestService.cs:1894

Technician change detection is inconsistent. Comparing a nullable previousTechnicianId with request.TechnicianId treats null and Guid.Empty as different. This sends an 'assigned to you' message to the requester when there is no technician. Unassigning sends nothing, and the previous technician is never notified. Normalize both sides before comparing and handle unassign explicitly.

F3 src/Modules/Sdm/Sdm.Application/Services/RequestService.cs:1933

Reopen classification treats Cancelled as open. isOpenLike = !IsClosedOrResolved(newCode) treats Cancelled (and null/unknown code) as open, so moving Resolved→Cancelled fires a 'Reopened' notification. Define reopen explicitly as new status in Open/InProgress/OnHold.
