This PR fixes venue/resource-schedule conflict messaging across EMS and RMS: previously, conflict/eligibility results carried a "message key" (e.g. dotted strings like ems.eventVenue.validation.unavailableForSchedule) that never matched any real resource entry in the .resx files, so end users would have seen a raw, untranslated key instead of a real error message. This PR replaces that with IStringLocalizer<Localizer>-resolved messages backed by newly added, correctly-named resx entries (English, default, and Arabic), and deletes the now-dead EventVenueScheduleValidationMessageKeys constant classes in both modules. It also adds a new POST /resource-schedules/check-existing endpoint (query, handler, validator, DTOs) that checks whether an active schedule already overlaps a given resource/date range.

Overall this is a well-scoped, backend-only bug fix that follows established codebase conventions (CQRS query/handler/validator triplet, IStringLocalizer<Localizer> injection, the same date-overlap formula used elsewhere in the module). No must-fix issues were found. The main gaps are a few unused new locale keys, missing test coverage for the new conflict-check logic despite the PR checklist claiming tests were added, and minor resx formatting inconsistency.
