This PR adds five new fleet masters to the UI: department, job title, operator type, vehicle source and inspection checklist. Each has services, resolvers, lazy-loaded routes, list and detail pages and column configs. It also adds TableType, menu ID and document type constants, and repoints some shared lookup endpoints.

Two things block merge. First, the TableType enum renumbers the existing FleetOperatorUnavailability from 412 to 417, which can break saved column selections and backend alignment. Second, the vehicle-source page can wipe a source's stored permissions if the permission-module lookup fails or hasn't returned when the user saves.

The team should confirm the backend routes for the changed lookups (vehicleSources, fleetDepartments, sources/lookUpByDepartment). They should also decide whether to split this ~4.8k-line PR. The description is the unfilled template, and no tests are visible.

Method: 9 independent review calls over 3 shard(s), evidence machine-checked (0 unverifiable candidates discarded), then one merge call.

F1 libs/core/enums/src/lib/enums/table-type.ts:419

Existing TableType value renumbered. New members were inserted at 412-416, so the existing FleetOperatorUnavailability moved from 412 to 417. TableType is sent to or stored by the user-columns API and must match the backend enum. Renumbering breaks saved column selections for Operator Unavailability. F2 libs/features/fleet/src/lib/master/vehicle-source/containers/vehicle-source-detail-page/vehicle-source-detail-page.component.ts:51

Failed permission lookup wipes permissions on save. If getPermissionModules() errors it is swallowed with of([]). The details component builds permission rows only from the module list (#buildPermissionRows), and #toVehicleSource maps only those rows into sourcePermissions. With an empty list, an existing fleet source's stored permissions are sent as [] and may be deleted by the backend. The same happens if the user saves before the lookup returns. Fix: surface the error, block save until modules load, or keep existing permissions that have no matching module row.

Notes

F9 libs/core/fleet/src/index.ts:104

INITIAL_* naming differs from siblings. Existing exports use camelCase factory/values (initialVehicle, initialCheckpoint, initialFuelCard, initialContact). The new ones use UPPER_SNAKE (INITIAL_DEPARTMENT etc.). These are mutable-shaped objects, not true constants, and the arrays inside (sections: [], sourcePermissions: []) are shared by reference, so a consumer that mutates them would corrupt the shared initial value. Prefer camelCase and copy or factory usage for consistency.
