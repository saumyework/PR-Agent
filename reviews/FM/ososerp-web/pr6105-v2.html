This PR converts the Role widget into the Fleet module. It adds a role-management list and details page, a widgets tab, an add-widgets drawer, a service that proxies to Configuration's role service, and en-US and ar-OM i18n keys. It also renames the fleet admin route to administration. The PR is open, and its description is the unfilled template.

Two things block merge. The FLEET_ADMIN_MANAGE_ROLES menu id (flt.administration.manageRole) doesn't match the sibling fleet.* ids, and it drives the route permission and menu, so a wrong id would deny access or hide the page. The Arabic strings in ar-OM.json also look mojibake-corrupted, so the file's encoding needs checking and fixing.

The team should decide four things. First, is the admin to administration rename intentional, and were navigator links updated? Second, should widget assign and unassign be gated by a write grant? Third, should Fleet keep reusing Configuration translation keys? Fourth, should the write proxies stay on a read-only service? Also verify that the template ref #widgetsTab compiles when it is used outside its mat-tab. Tests are missing too.

Method: 4 independent review calls over 1 shard(s), evidence machine-checked (0 unverifiable candidates discarded), then one merge call.
