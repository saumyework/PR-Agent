This PR converts the role widget feature into Fleet. It adds a read-only role management list and details page, a widgets tab, an add-widgets drawer and a widget card. It also adds routes, MENUIDs, and en-US and ar-OM translations.

Nothing here is a clear must-fix, but several items should be fixed before merge. The assign-versus-update decision is made from state that may not have loaded yet. The admin to administration route rename is unexplained and may break links. The list route has no permission data. The drawer subscriptions have no teardown. The PR description is empty and there are no tests.

The team should confirm that menu ids and backend permission mappings match the renamed route and the new flt.administration.manageRole id.

Method: 4 independent review calls over 1 shard(s), evidence machine-checked (0 unverifiable candidates discarded), then one merge call.

F1 libs/features/fleet/src/lib/admin/role-management/components/role-management-widgets-tab/role-management-widgets-tab.component.ts:60

Assign vs update from unloaded state. handleAddWidget reads roleWidgets(), which is null until the load finishes, or if it fails. The drawer then opens with nothing preselected and saveWidgets calls assign (POST) instead of update (PUT), which can conflict with existing assignments. loadRoleWidgets and the save calls have no error handling, and isLoading is not set. Disable Add until the load completes, and consider disabling Save on an empty selection when nothing is assigned.
