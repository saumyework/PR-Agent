This PR adds a Traffic Violation feature to the Fleet module (FM-816). It has an entity, a service, CQRS commands and queries, and endpoints for CRUD, unique code generation and assigned drivers by vehicle.

Two issues block merge. VehicleId and OperatorId are not validated against the caller's company, which allows cross-tenant references and leaks another tenant's vehicle and operator data. GetById, Update and Delete also operate on soft-deleted rows.

The code is generated at random with no uniqueness check on update. Validation is thin, the assigned-drivers query needs fixing, and there are no tests. The team should confirm the unique index exists and decide whether to use DocumentCodeSetup for code generation.

Method: 4 independent review calls over 1 shard(s), evidence machine-checked (0 unverifiable candidates discarded), then one merge call.

F1 src/Modules/Fleet/Fleet.Application/Services/TrafficViolationService.cs:59

VehicleId/OperatorId not validated against company. CreateAsync and UpdateAsync (via ApplyTo) assign VehicleId and OperatorId from the request without checking that they exist, aren't removed, and belong to the caller's company. A caller can link a violation to another tenant's vehicle or contact, and the DTO then returns that tenant's vehicle and operator details. Non-existent ids cause FK 500s. Validate both ids against companyId before saving. Do the same in the assigned-drivers query. Also at: src/Modules/Fleet/Fleet.Application/Services/TrafficViolationService.cs:61, src/Modules/Fleet/Fleet.Application/Services/TrafficViolationService.cs:39.

Soft-deleted rows returned by GetById/Update/Delete. GetForCompanyAsync filters only on Id and CompanyId, not Status != Removed. Removed violations can be read, edited and deleted again. F3 src/Modules/Fleet/Fleet.Application/Services/TrafficViolationService.cs:30

Code uniqueness not enforced on update; create is racy. UpdateAsync overwrites TrafficViolationCode from the client via ApplyTo with no uniqueness check or immutability guard. Create uses a check-then-insert with a random 6-digit code, which can race without a unique index. Random.Shared.Next(100000, 999999) never returns 999999. The existing DocumentCodeSetup sequence isn't used. Make the code immutable on update, add a unique index on (CompanyId, TrafficViolationCode), and consider DocumentCodeSetup. Also at: src/Modules/Fleet/Fleet.Application/Services/TrafficViolationService.cs:135.
