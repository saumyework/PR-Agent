Adds Fleet Widget CRUD (list, get, lookup, create, update, soft delete) with a new Widget.Name field and random WG- codes, plus role-widget assignment endpoints (assign, sync-update, unassign, get by role). The PR description is the unfilled template.

Risk: High. Two defects stop this from working at all. The Arabic resx is malformed XML, which breaks the build (F1), and Widget.Name has no migration, so every widget query fails at runtime (F2). Beyond those, role and widget ids are never verified (F3), and the sync update can commit removals and then fail on the inserts, silently dropping a role's widgets (F4). The layering and soft-delete handling are otherwise clean and follow the Fleet siblings.

Review process: three independent passes (file order, reverse order, request flow), merged and verified against the head commit, then one gap pass, which came back empty. All 36 files were reviewed; there were no generated files to skip.

F1 src/BuildingBlocks/BuildingBlocks.Locale/Resources/Locale/Localizer.ar-OM.resx:4427

Arabic resx is malformed XML. The new WidgetIdsRequired entry has no closing </data>, so the following ItemFinanceCategoryTypeRequired element opens inside it. The file is no longer valid XML, so resource generation for BuildingBlocks.Locale fails the build (or, at best, Arabic resources fail to load). The en-US and neutral files are correct. Add </data> after line 4428.

F2 src/Modules/Fleet/Fleet.Domain/Models/Widget.cs:19

New column, no migration. [Required] public string Name is added to Widget, but there is no migration and no *ModelSnapshot.cs change for either PostgreSQL or SqlServer. At head, the latest Fleet migrations are ..._ConfigureVehicleFuelEconomyColumnNames, and FleetPostgresDbContextModelSnapshot (line 6487) has no Name on Widgets. Every widget query (list, get, lookup, NameExistsAsync, the role-widget include) and every insert will fail with "column Name does not exist". Add a migration for both providers, with a default or backfill for existing (e.g. legacy-migrated) widget rows, since the column is non-null.

F3 src/Modules/Fleet/Fleet.Application/Services/RoleWidgetsService.cs:43

Unverified role and widget ids. AssignAsync, and SyncAsync through it, insert a RoleWidgets row for whatever GUIDs the client sends. Neither the service nor the validators load the Role or the Widgets. An unknown widgetId fails on the FK at SaveChanges and surfaces as a 500 instead of a validation message. A deleted role (Role.IsDeleted) or a Status.Removed widget is accepted silently, then hidden by GetByRoleIdAsync, leaving orphan rows. Add service-backed MustAsync rules (sibling pattern): the role exists and isn't deleted, and every widget exists and is Active. Also, the RoleWidgets UpdateCommandValidator (RoleWidgets/Commands/Update/UpdateCommand.cs:22) and UnassignCommandValidator lack the RuleForEach(...).NotEmpty() that Assign has, so Guid.Empty ids get through.

F4 src/Modules/Fleet/Fleet.Application/Services/RoleWidgetsService.cs:87

Non-atomic sync loses data. SyncAsync calls UnassignAsync, which commits its own SaveChangesAsync, and only then calls AssignAsync, which saves again. If the insert fails (e.g. an invalid widget id, see F3), the removals are already committed. The request returns 500 and the role has fewer widgets than before. The same role's rows are also read up to three times. AddAsync/DeleteAsync on the list only stage changes, so compute both sets from the single load, stage both, and call SaveChangesAsync once (or use a transaction, per the C# guide's "Database Transaction Handling").

But ApplyTo copies only Name and Description, so a PUT with a new URL returns 200 and keeps the old one. The Widget UpdateCommandValidator also has no URL rule. F6 src/Modules/Fleet/Fleet.Application/UseCases/Widgets/Commands/Create/CreateCommand.cs:23

F7 src/Modules/Fleet/Fleet.Application/Services/WidgetService.cs:53

Trim mismatch in duplicate check. NameExistsAsync compares name.Trim().ToLower() with the stored x.Name.ToLower(), but ToEntity/ApplyTo save dto.Name untrimmed. After saving "Fuel ", a later "Fuel" is not detected as a duplicate. Trim the name on save. (ToLower() on the column also prevents index use.)

F8 src/Modules/Fleet/Fleet.Application/Services/RoleWidgetsService.cs:45

Races without unique indexes. Uniqueness of (RoleId, WidgetId) (the AssignAsync in-memory dedupe), WidgetCode (the GenerateUniqueCodeAsync loop) and widget Name (NameExistsAsync) is enforced only by read-then-write checks. The snapshot has only a plain HasIndex("WidgetId") on RoleWidgets, so a double-click or concurrent requests can insert duplicates. Add unique (status-filtered where needed) indexes in the migration F2 already requires.

F9 src/Modules/Fleet/Fleet.Application/Services/WidgetService.cs:107

Ad-hoc code generation. Widget codes are random WG-###### values, with an AnyAsync round-trip per attempt. Sibling VehicleService generates codes through the DocumentCodeSetup sequential-code mechanism (GetSequentialCodeSetupAsync). The PR's approach can't be configured the way other document codes can, and without an index (F8) it can still collide under concurrency. Reuse the code-setup mechanism, or justify the deviation.

F10 src/Modules/Fleet/Fleet.Application/Services/WidgetService.cs:84

Delete doesn't cascade. DeleteAsync only sets Widget.Status = Removed. RoleWidgets rows and UserDashboardWidget rows (which also reference WidgetId) remain. AssignAsync/SyncAsync still count them as assigned, and any reader that doesn't join Widget.Status still shows the widget. Either cascade the soft delete, as sibling DocumentCodeSetupService.DeleteAsync does for its children, or block deletion while the widget is assigned.

F11 src/Modules/Fleet/Fleet.Application/Services/RoleWidgetsService.cs:81

Inconsistent delete model. RoleWidgets has a Status, and Assign sets it to Active, but UnassignAsync physically deletes rows and no query ever filters on RoleWidgets.Status. The module convention (and this PR's own WidgetService) is soft delete via Status.Removed. Pick one model: soft-delete and filter on it, or stop writing an unused column.

F12 src/Modules/Fleet/Fleet.Application/Services/RoleWidgetsService.cs:27

Role name derived from assignments. RoleName comes only from the joined RoleWidgets rows. A valid role with no widgets yet (the normal starting state) returns RoleName = "", and a non-existent or deleted roleId returns 200 with an empty payload instead of 404. Load the role directly and throw NotFoundException when it is missing or IsDeleted. GetByRoleIdQuery also has no validator for an empty RoleId.

F13 src/Modules/Fleet/Fleet.Application/Endpoints/RoleWidgetsEndpoints.cs:21

Cross-company role access. Role is company-scoped (CompanyRole, IsGlobalRole), but any caller can read or rewrite the widget set of any roleId. Nothing checks that the role belongs to the caller's company, and the group adds no permission requirement beyond activity logging. Confirm this is guarded upstream, or scope the role lookup (see F3/F12) to the caller's company.

F14 src/Modules/Fleet/Fleet.Application/Endpoints/RoleWidgetsEndpoints.cs:23

RPC-style routes. C# guide 5.1.1 says the HTTP verb carries the action ("no need to include the action name in the route segment"), and 5.1.2 says non-PK lookups use /propertyName/{value}, as sibling documentCodeSetups/companyId/{companyId:guid} does. This file uses /assignWidgets, /updateAssignedRoleWidgets, /unassignWidget (query-string ids) and /byRole?roleId=. Suggested: POST /, PUT /, DELETE /roleId/{roleId:guid}/widgetId/{widgetId:guid}, GET /roleId/{roleId:guid}.

F15 src/Modules/Fleet/Fleet.Application/Endpoints/RoleWidgetsEndpoints.cs:27

Unassign returns 200 with false when the link doesn't exist (line 45), where 404 would be right. Widget Delete (WidgetEndpoints.cs:41) also always returns Ok(true). Return the resulting RoleWidgetsDto or 204, and 404 for missing links.

What's Good

Thin handlers, services behind interfaces. Endpoints and handlers only delegate to [ScopedService] primary-constructor services, with MapToDto/ToEntity/ApplyTo extensions and a GetIncludes() pattern matching the DocumentCodeSetup siblings.

Consistent soft delete for widgets. Widget reads and writes all exclude Status.Removed through one GetActiveOrThrowAsync helper that throws NotFoundException, which is stricter than some older Fleet get-by-id services.

Server-side lookup projection. GetActiveLookupAsync projects to WidgetLookupDto with ordering in the query, instead of loading full entities.

Idempotent assign. AssignAsync de-duplicates the input, skips already-assigned widgets and batches the insert with one SaveChanges.

Localized validation. Every new message goes through Locale constants with neutral, en-US and ar-OM entries (apart from the F1 XML defect).
