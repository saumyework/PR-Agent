Adds two new slices to the Fleet module's Application layer (backend only, 34 files, +1154/−1): Company Settings (list and get-by-company endpoints that merge active EDM companies with the Fleet CompanyIvmsSetting row) and Document Code Setup (create, update, soft-delete, get-all, get-by-id, get-by-company, an ensure provisioning command and an active lookup over the existing DocumentCodeSetup/DocumentFormat entities). It follows the module's CQRS/service/extension-mapper structure and uses EnterpriseDataManagement.Contracts for cross-module company access.

The main risk is data integrity on the write path: nothing prevents duplicate company/module setups, and the validators leave the document-numbering fields (SerialNo, FormatLength, Status) unconstrained. Separately, the Company Settings list bypasses the generic pagination/sort/filter engine, and several mapped company fields look like they will always be null. No tests are included.

Errors Warnings Notes Passed

Must-Fix

src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:101

No uniqueness guard on company + module. CreateAsync and UpdateAsync take CompanyId/CodeModuleId straight from the DTO (ApplyTo rewrites both on update) with no check that the pair is unused, or that the company and code module exist. EnsureForCompanyAsync dedupes by CodeModuleId, but Create bypasses it, and two concurrent ensure calls can both insert the same rows. I found no unique index on the pair in FleetDbContext.cs (worth confirming in the migrations). Duplicate setups for one company/module mean two prefixes and two serial counters for the same document type. Add a duplicate check in CreateAsync, make CompanyId/CodeModuleId immutable on update (or re-check them), and back it with a unique index.

src/Modules/Fleet/Fleet.Application/UseCases/DocumentCodeSetups/Commands/Create/CreateCommand.cs:21

Validators skip the numbering fields. CreateCommandValidator (and the same in UpdateCommand.cs:21) only checks presence. Nothing constrains SerialNo (≥ 1), FormatLength (sane range), Prefix length, format FormatNumber/duplicate numbers, or Status (IsInEnum). Because Status is bound from the client, a POST/PUT can send Status.Removed and hide a setup without going through Delete, leaving its formats active. These values drive document number generation, so bad values produce broken or duplicate codes. Also, Locale.CodeRequired is reused for CodeType, Prefix and format Value, so the user can't tell which field failed.

Suggestions

src/Modules/Fleet/Fleet.Application/Services/CompanySettingService.cs:26

List bypasses the generic paging engine. GetAllAsync hard-codes OrderBy(CompanyCode) and applies only skip/top; orderby, filter, jsonFilter and ReturnAll on PaginationRequest are ignored, and it returns []/null for FavoriteIds/Columns. Column sort, filter and search on this list will silently do nothing, unlike DocumentCodeSetupService.GetAllAsync which goes through repository.ListAsync. Route the list through ListAsync (EDM's CompanyService already pages companies that way) or apply the criteria builder before Skip/Take.

src/Modules/Fleet/Fleet.Application/Extensions/CompanySettingExtensions.cs:37

Several mapped fields likely always null. On Company, ReportingCurrency and Logo are [NotMapped]; Company.GetIncludes() (used by GetActive()) loads Country but not BaseCurrency; and the list path returns plain Company entities, so company as CompanyConfigResponse is always null there (no logos/stamps). On the by-id path CompanyService.GetAsync(Guid) loads the company without includes. Expect ReportingCurrencyName, BaseCurrencyName, CompanyLogo and DetailStampUrl (and possibly CountryName) to be empty. Please verify against real data, and either load them explicitly or drop the fields from the DTO.

src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:76

Removed setups still readable and updatable. GetAll and GetByCompanyId exclude Status.Removed, but GetByIdAsync (and the fetch at line 121 in UpdateAsync) do not. A soft-deleted setup can still be fetched by id, and a PUT with Status = Active resurrects it. Treat Removed as not found in both paths so behavior matches the list endpoints.

src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:107

Null and stale format input. CreateAsync dereferences dto.Formats.Count, so a request with "formats": null throws a NullReferenceException (500) — SyncFormatsAsync guards this with ??= [], Create doesn't. In SyncFormatsAsync (line ~193) a format with a non-empty Id that isn't among the setup's existing formats is silently skipped, so the caller gets a 200 with data that wasn't saved. Guard the null in the validator or service, and throw NotFoundException/a validation error for unknown format ids.

src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:88

A dropdown built from it will show the same short code once per company with no way to tell them apart. Confirm the intended consumer: either filter by company (or take a companyId), or return CodeModule ids/names instead.
