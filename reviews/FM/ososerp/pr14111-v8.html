Document-code provisioning moves out of CompanySettingService into EnsureForCompanyAsync. Some unrelated VehiclePlate cleanup is bundled in.

This is the complete, consolidated review of commit 22d418d and replaces v1â€“v7. It was produced by three independent full review passes, merged and checked against the code, followed by gap-finding passes until one found nothing new. Everything from v7 is included (F1, F6, F8, F14, F17, F19). Future reviews of this PR will only re-check these IDs and look at newly pushed code.

Blocking: the API accepts Status values it shouldn't (F1), lets an update move a setup to another company or rewind its serial number (F2), and returns 500s for non-existent company or module ids (F3). F4 (company scoping) needs a decision from the team before merge.

Errors Warnings Notes Passed

Must-Fix

F1 src/Modules/Fleet/Fleet.Application/UseCases/DocumentCodeSetups/Commands/Create/CreateCommand.cs:22

Status is never validated. Neither validator checks Status on the setup or on its Formats. ToEntity/ApplyTo copy it straight from the request. As a result: (a) POST with status: 2 (Removed) commits the row, then CreateAsync returns GetByIdAsync, which filters out Removed, so the client gets a 404 for a row that was saved. (b) PUT with Removed soft-deletes the setup outside DeleteAsync, so its formats are never cascaded. (c) Out-of-range values like 99 are stored. Fix: add .IsInEnum() and restrict the setup and every format to Active/Inactive, in both CreateCommand and UpdateCommand. Only Delete should set Removed.

F2 src/Modules/Fleet/Fleet.Application/Extensions/DocumentCodeSetupExtensions.cs:60

Update can move a setup or rewind its serial. ApplyTo overwrites CompanyId and CodeModuleId from the PUT body, and UpdateAsync loads by Id alone. A PUT can therefore move an existing setup, with its formats and serial counter, to another company or module. Its Prefix ({companyCode}-{ShortCode}) then points at the wrong company. SerialNo can also be set lower than numbers already issued, so later documents reuse existing numbers. Fix: treat CompanyId/CodeModuleId as immutable on update (don't apply them, or reject the request if they differ), and don't allow SerialNo to decrease.

F3 src/Modules/Fleet/Fleet.Application/UseCases/DocumentCodeSetups/Commands/Create/CreateCommand.cs:23

Company and CodeModule existence not checked. Create and Update only check NotEmpty() on CompanyId/CodeModuleId (also UpdateCommand.cs:23). A random GUID passes validation and then fails the FK in SaveChangesAsync, so the client gets a 500 instead of a localized 400. An inactive CodeModule is accepted, even though Ensure only provisions Active modules. Fix: add MustAsync rules that check the company exists and is active, and the CodeModule exists with Status.Active.

Suggestions

F4 src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:29

No company scoping on list, get, update and delete. GetAllAsync returns every company's setups (only Status != Removed). GetById/Update/Delete act on any Id, and Create/Update trust the body's CompanyId. Meanwhile /lookup scopes by the caller's CompanyCode header. Decide which model is intended: either an admin-only cross-company screen (then enforce that with a permission on the group), or filter every query and write by the caller's company.

F5 src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:121

Null formats crashes Create. A body with "formats": null overrides the = [] initializer. RuleForEach skips a null collection, then dto.Formats.Count throws a NullReferenceException (500). Null items inside the array fail the same way. Update already guards against this with incomingFormats ??= []. Fix: add RuleFor(x => x.DocumentCodeSetup.Formats).NotNull() plus a per-item NotNull, or use dto.Formats ?? [].

F6 src/Modules/Fleet/Fleet.Application/UseCases/DocumentCodeSetups/Queries/GetActiveLookup/GetActiveLookupHandler.cs:22

Lookup crashes on an unknown company code. CompanyByCodeQuery returns a null Company for an unknown or missing code, and company.Company.Id throws a NullReferenceException (500). The other two company-resolving handlers in this PR null-check and throw NotFoundException. Do the same here.

F7 src/Modules/Fleet/Fleet.Application/UseCases/DocumentCodeSetups/Commands/Create/CreateCommand.cs:29

Remaining validation gaps. These are in both validators. Each format's FormatNumber has no rule, so 0, negative and duplicate values within a setup are accepted. CodeType is free text, although the only known value is DocumentCodeSetupDefaults.SequentialCodeType. No MaximumLength on Prefix/CodeType/DocumentReferenceNo/PrintHeaderFooter/Value to match the DB columns. FormatLength/SerialNo have no upper bound, and nothing checks that SerialNo fits in FormatLength digits.

F8 src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:209

Format sync silently drops edits. In SyncFormatsAsync, an incoming format whose non-empty Id isn't among this setup's active formats (stale, removed, or from another setup) is skipped with continue. The edit is lost and PUT still returns 200. Also, a PUT that omits formats removes every existing format. Fix: reject unknown format Ids with a validation or NotFound error, and document or guard the omit-means-delete-all behaviour.

F9 src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:106

Duplicates possible under concurrency. Uniqueness of (CompanyId, CodeModuleId) is only check-then-insert: AnyAsync in the validator, and the existing-setups read in EnsureForCompanyAsync. DocumentCodeSetupConfiguration has no unique index, so a double-clicked Create or two concurrent /ensure calls both insert. Fix: add a filtered unique index on (CompanyId, CodeModuleId) WHERE Status <> Removed and map the violation to DocumentCodeSetupAlreadyExistsForCompany.

F10 src/Modules/Fleet/Fleet.Application/Services/DocumentCodeSetupService.cs:48

Ensure treats deleted setups as existing. EnsureForCompanyAsync loads setups with no status filter, so a module whose setup was soft-deleted is never provisioned again. The Create duplicate check does ignore Removed rows, so the two paths disagree about what "exists" means. Filter x.Status != Status.Removed, or restore the removed row, whichever the business intends.

F11 src/Modules/Fleet/Fleet.Application/UseCases/DocumentCodeSetups/Commands/Ensure/EnsureHandler.cs:21
