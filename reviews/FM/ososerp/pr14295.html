feat(Fleet): Traffic violation [FM-816]

Risk: High
3Errors 8Warnings 1Notes 4Passed

This PR adds a Traffic Violation feature to the Fleet module. It includes a service, CQRS commands and queries, endpoints, mapping extensions, and an assigned-drivers-by-vehicle lookup. Reads and writes are scoped by company and Delete is a soft delete.

Merge is blocked by three problems. VehicleId and OperatorId are not checked against the caller's company, which allows cross-tenant references and data exposure. Update can overwrite the code without a uniqueness check. The single-record lookup does not exclude soft-deleted rows, so removed records can be read, edited and deleted again.

The team should decide on code generation (the random check-then-insert scheme versus the DocumentCodeSetup mechanism used by sibling modules, plus a unique index) and on the endpoint contract (POST for a read, Ok(bool) on delete). The PR also has no description and no tests.

Method: 4 independent review calls over 1 shard(s), evidence machine-checked (0 unverifiable candidates discarded), then one merge call.
