A performance PR (118 files, +650/−158) with four parts. (1) The app shell and every lazy route or @defer import now use one-export entry files (@osos/shared-components/entries/*, @shared-features/entries/*) instead of the barrel. EmptyRoleDialogComponent and RequestWidgetDialogComponent now load on demand, which keeps Syncfusion out of the startup chunk. (2) The two Vizzly <script> tags leave index.html. A new VizzlyScriptLoaderService injects them when one of the 5 dashboard components needs them. Those components now get the element through viewChild instead of the implicit window.dashboard global. (3) Build-time fixes: all 45 libraries rename build → build-lib, three component stylesheets drop their Syncfusion theme imports, Tailwind stops scanning .scss, a .dockerignore is added, and a lint-staged guard is added. (4) gzip is turned on in nginx.conf.

The change is mechanically sound. Each entry file re-exports the same source module as the barrel, so class identity and providedIn: 'root' singletons are unchanged. I checked the repo tree: no component outside the 5 updated ones renders <vizzly-dashboard> or uses the global. Nothing blocks merge. Risk is Medium because the PR touches the startup path, build config for every library and the production nginx config, and because the new lazy-load points have no failure handling. The PR description is also still the empty template.

F1 libs/shared/components/src/lib/shared-components/request-widget-launcher/request-widget-launcher.component.ts:72

New lazy-load points fail silently. Code that used to sit in the main bundle is now fetched at runtime, but none of the new fetch points handles a failure. Right after a deployment, a user with an open tab asks for chunk hashes that no longer exist and gets a 404. A network blip has the same effect. Where it shows up: RequestWidgetLauncherComponent.open() uses try/finally with no catch, so clicking the launcher does nothing and leaves an unhandled rejection. AppComponent.#emptyUserRolesErrorMessage (src/app/app.component.ts:279) turns a failed import() into an error in the role-check stream, so the empty-role message never appears. VizzlyScriptLoaderService.load() rejects into un-caught async callbacks in all 5 callers (dashboard-layout.component.ts:153, insight-hub.component.ts:286 in appraisal, the effect IIFEs in the HR/L&D insight hubs at line 84, and the recruitment dashboard.component.ts), so the dashboard stays blank with no message. Add a catch at each point that shows a SnackBarNotificationService error, or better, one global chunk-load-error handler that offers a reload. Also, #loadScript should remove the failed <script> element in onerror. Otherwise every retry adds another dead tag to <head> (libs/core/src/lib/core/services/vizzly/vizzly-script-loader.service.ts:41).

Notes

F3 package.json:13

build:dev/build:all changed meaning. No library has a build target any more, so nx run-many -t build (build:dev) and nx run-many -t build --all --parallel=2 (build:all) now build only the ososerp-web app. The scripts still read as "build everything". This is fine for CI (nx_build_pr.yml → nx affected --target=build resolving to the app is the intended win), and the pre-push hook now runs lint:all anyway. But the team docs (the Husky page quoted in the Angular guide still says pre-push runs yarn build:all as a "full repo build") and these script names should say that libraries are now only compiled through the app, or via the new build:libs.

F4 libs/shared/components/src/lib/shared-components/request-widget-launcher/request-widget-launcher.component.ts:37

Launcher polish. Rename #opening to #isOpening (Naming guide: boolean prefixes). let RequestWidgetDialogComponent; is an untyped, PascalCase local that shadows the class name. const { RequestWidgetDialogComponent } = await import(...) inside the try, with the open call also inside it, reads more cleanly. Also, the isVisible()/getDialogById guards run only before the await. If the user navigates to a route where the widget is disabled while the chunk downloads, the dialog still opens there. Re-check isVisible() after the import.

F5 scripts/check-syncfusion-theme-imports.js:42

Guard script edge cases. The script skips only lines that start with //. An import commented out with /* … */, which is common in .css files where // isn't valid, still fails the hook. IMPORT_RE also needs quotes right after @import, so @import url('…@syncfusion/…') passes. Both are small gaps in a new guard. Strip block comments before matching and allow an optional url(.

What's Good

libs/shared/components/src/entries/README.md

Root cause fixed, and documented. The entries/ pattern targets the actual problem: Syncfusion packages without sideEffects: false become reachable through the barrel. The README explains when to use entries and when the barrel is still fine. Removing the relative cross-lib import in default.component.ts also fixes a module-boundary violation.

libs/core/src/lib/core/services/vizzly/vizzly-script-loader.service.ts

Clean, idempotent loader. It caches the in-flight promise with ??=, clears the cache on failure so a retry works, loads scripts in order, and uses DOCUMENT instead of the global. It lives in core with no dependencies on other libraries, as the architecture rules require.

libs/shared/components/src/lib/shared-components/vizzly-dashboard/dashboard-layout/dashboard-layout.component.ts:103

Global replaced with viewChild. The implicit window.dashboard global broke once the element was upgraded after Angular had set id. Switching all 5 components to viewChild<ElementRef<…>>('vizzlyDashboard') fixes that regression and removes a fragile declare let. I checked the tree at head: no other component renders <vizzly-dashboard>.

nginx.conf:7

Sensible gzip config. It excludes formats that are already compressed (woff/woff2, images), sets gzip_vary for caches, and uses gzip_proxied any for traffic through the ingress. The Task 21 doc includes the post-deploy curl check for the ingress.

scripts/check-syncfusion-theme-imports.js

Regression guard added. The three re-added Syncfusion theme imports are removed, and a lint-staged check plus yarn check:syncfusion-styles now stop a >10-minute build regression from coming back unnoticed.
