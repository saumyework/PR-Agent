refactor(UI): Update barrel exports and simplify import paths [OBPP-0000]

Risk: Medium
2Errors 2Warnings 1Notes 3Passed

This PR flattens libs/core's internal barrel structure: all 126 nested index.ts re-export files under libs/core/src/lib/** are deleted, and every internal import that used to go through them is rewritten to import directly from the concrete source file. The single library-level barrel, libs/core/src/index.ts, is rewritten from ~100 wildcard export * from lines into ~1,415 explicit named exports pointing at concrete files. In total 743 files change — 617 modified (import-path rewrites only), 126 removed (deleted barrels), across every domain in libs/core.

This is a mechanical, tool-generated refactor rather than a hand-written change. Given the scale, this review verified correctness by sampling representative diffs across small and large files, multiple domains (appraisal, recruitment, dashboard, self-service, core utils), and the two files outside libs/core that were also touched — every sample showed the exact same set of imported symbols preserved, just resolved to concrete file paths, with no logic changes mixed in. A duplicate-export scan against the new libs/core/src/index.ts (covering the ~1,035 single-symbol export lines directly, plus a partial pass on the remaining multi-symbol lines) found no collisions.

The one systemic issue is that the generated import statements use double quotes throughout, while the repo's Prettier config (singleQuote: true) and the Angular guide both require single quotes — and there's no green CI/build check on this PR to catch it. Given the blast radius (this is the app's single shared core library), that combination is the basis for the Medium risk rating rather than any logic bug found.

Must-Fix

libs/core/src/index.ts (and all 616 other modified files)

Generated imports use double quotes, violating the project's Prettier config. Every new/rewritten import and export statement in this PR (e.g. import { RatingType } from "../../appraisal/enums/rating-type"; in libs/core/src/lib/core/utils/get-enum.ts) uses double quotes, but .prettierrc.json at the repo root sets "singleQuote": true, and the Angular guide explicitly calls out single quotes as the standard. This is consistent across essentially all 743 changed files — the two files outside libs/core (libs/features/configuration/.../table-metadata.ts ×2) were edited by hand and correctly kept single quotes, confirming the double-quote pattern is specific to whatever codemod produced the bulk change. The repo's Husky pre-commit hook is supposed to run prettier --write on staged files automatically, so this surviving into the PR suggests the hook was bypassed for this commit. Run yarn prettier --write across the changed files (or re-run the codemod with the correct quote style) before merge.

PR #6013

No passing build/lint check exists for a change to the shared core library. gh pr checks shows only a PR_Title check — nothing validates that the app (or even just libs/core) actually builds after this change. libs/core is the single shared foundation library every feature and shared library depends on, and a change touching 743 of its files with no CI signal means a dropped export, a bad relative path, or a duplicate export name (which would fail TypeScript compilation) has no automated safety net here — only whatever the author ran locally before pushing (the repo's own Husky pre-push hook runs a full yarn build:all, so if that ran and passed, say so in the PR description). Given the review sampling found the transform to be mechanically correct everywhere it was checked, this is flagged as a process gap rather than a known bug — but confirm the full build was actually run green before merging a change this size with zero CI coverage.

Suggestions

libs/core/src/index.ts

New multi-symbol export lines far exceed the configured print width. Lines like the resolver re-export near the top of the file (export { activeAllEmployeesResolver, companyIdResolver, currenciesResolver, ... } from "./lib/self-service/services/recruitment-requests.resolver";) run to several hundred characters, well past the printWidth: 80 Prettier is configured for. Running Prettier (see the quote-style Must-Fix above) would also wrap these onto multiple lines and make the file's diff-review-ability much better for future changes to this barrel.

guides/Angular Code Review.txt

This PR reverses the team's documented barrel-usage convention. The Angular guide's "Index Files" section says to "use index.ts files to group and re-export public APIs in shared or domain libraries," which is exactly what the 126 deleted files were doing. If flattening internal barrels into direct deep imports (for better tree-shaking / avoiding the barrel-bloat problem) is now the intended convention for libs/core, update that section of the guide so future contributors don't reintroduce nested barrels the next time they add a domain to core.

What's Good

libs/core/src/index.ts

Legitimate, verified-correct performance motivation. Replacing export * from barrel chains with explicit named exports is a well-known fix for Angular/Nx bundle-bloat and slow incremental builds caused by deep barrel graphs — it lets the bundler tree-shake per-symbol instead of pulling in whole barrel subtrees. Spot checks (get-enum.ts, recruitment-requests.resolver.ts, table-metadata.ts, target-distribution.helper.ts) all show the exact same imported-symbol set preserved before and after, just resolved to concrete paths.

libs/features/configuration/.../table-metadata.ts:1

Fixed a pre-existing Nx module-boundary violation as a side effect. Both feature-library files touched outside libs/core previously reached into core's internals via a long relative path ('../../../../../../../core/src/lib/dashboard/models') instead of the public @osos/core alias. This PR consolidates both into a single proper @osos/core import, which is exactly the right fix regardless of the rest of the refactor.

libs/core/src/index.ts

No duplicate exports found in the new consolidated barrel. The single highest-blast-radius risk in a change like this — two files independently exporting a symbol with the same name, which would break the TypeScript build — wasn't found in this review's scan of the new root barrel.
