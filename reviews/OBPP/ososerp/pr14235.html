This PR is already merged, so any fixes need a follow-up PR. It adds a formula builder: a formula engine (type checker, compiler, function catalogue), versioned formulas, effective-dated derived-field bindings and a field-process resolve endpoint. It also passes the document type into the dynamic save pipeline and adds localization and tests. At about 18k lines across 298 files with an empty description, it should have been split.

The main blocker is in binding writes. FieldBindingService.CreateAsync closes the current binding outside the transaction, and global bindings (null DocumentTypeId) have no uniqueness on PostgreSQL. Other integrity problems: a dependency cycle is persisted before it is detected, the compilation cache is never invalidated on publish, and closed bindings can be edited. Null JSON, unknown document types, and client-supplied record ids reach the services unchecked, which can give 500s or cross-tenant reads.

The team should confirm that the resolve endpoint and the query engine are tenant-scoped and covered by global authorization. It should also decide whether closed bindings should be immutable, and add the missing query validators.

Method: 19 independent review calls over 9 shard(s), evidence machine-checked (0 unverifiable candidates discarded), then one merge call.

F1 src/Modules/Kernel/Kernel.Application/Services/FieldBindingService.cs:58

Binding closed outside the transaction. CloseCurrentBindingAsync updates the current binding's end date before the transaction begins. If the insert or RefreshInputsAsync fails, the tracked change can still be saved by a later SaveChangesAsync, or left inconsistent. Two concurrent creates can also both see the same open binding and insert two open rows, so SingleOrDefault later throws. Move the close inside the transaction and enforce uniqueness.

F2 src/Modules/Configuration/Configuration.Infrastructure/Data/Configurations/DerivedFieldBindingConfiguration.cs:20

Unique index misses global bindings on PostgreSQL. The unique index includes the nullable DocumentTypeId. PostgreSQL treats NULLs as distinct, so two global bindings for the same field and EffectiveFrom are allowed, while SQL Server rejects them. The service's check-then-insert guard is therefore racy. Add a filtered index or NULLS NOT DISTINCT for the null case.

F3 src/Modules/Kernel/Kernel.Application/Services/FormulaCompilationCache.cs:39

A draft version compiled and then edited would serve a stale compiled result. Call Remove on draft update and publish, and consider bounding the cache.

Layered formula engine with limits. Node compilers and type rules are cleanly separated, with duplicate-registration checks. Compile-time depth and node-count limits and a runtime call-depth limit protect against runaway formulas.
